# 头像发布与验收

部署前先执行 `supabase/20261105_avatar_lifecycle.sql`。迁移不删除已有对象；它设置头像列表/删除权限、64 个对象的每用户配额，以及头像引用存在性校验。新版本只接受编辑器导出的 256×256 PNG；旧客户端的固定文件覆盖被禁用。迁移与前后端代码应在同一发布窗口上线，回滚需配套恢复原上传策略。

预览和保存均从相同裁切 canvas 输出 256×256 PNG。页面直接上传该 File，不再二次缩小或有损压缩；保存失败重试复用 File 和已经上传的 URL。对象以用户 ID 加 SHA-256 命名，相同图片重试不会累积新对象。

每次上传会先回收本人超过 7 天且未被 profile 引用的对象，再检查配额。数据库策略与 profile 更新使用同一用户锁，阻止正在使用的头像被删除，阻止 profile 引用已删除对象。7 天保留期用于缓存、重试和回滚；64 个配额限制连续换图产生的对象数量。闲置账号的历史图片不会主动被扫描，但对象数量受配额约束。不要绕过 Storage API 直接删除 storage.objects 元数据。

本次迁移使用本地自动化测试验证头像编码校验、上传重试、清理筛选、配额处理和页面状态。未在本次工作中执行数据库迁移，未完成真实 Supabase Storage 或多连接锁竞争验收。真实部署需检查不存在其他宽松的 Storage 策略，并验证多个客户端并发保存/清理、Storage API 冲突状态和真实 RLS。

人工验收：使用有清晰边界和方向标记的图片，分别测试拖动、缩放、90°旋转，比较大预览、小预览和保存后头像；刷新页面后再次比较。测试失败重试、取消与重新选图、手机竖屏/横屏、键盘 Escape 和焦点恢复。PNG 在不同显示尺寸下会进行显示缩放，像素级匹配应比较实际 256×256 导出图。

RV 适配：头像入口位于个人资料弹窗，保留昵称保存与官方账号显示逻辑。Vercel 构建须包含 vendor/ 下的 Cropper 文件。两个部署使用同一数据库时，迁移只需执行一次。
